# DESIGN SYSTEM — AREF Open Data Centre (governing design law)

**Status:** Normative. The human-facing companion to `PA_MODE_CONTRACT.md`. Every future frontend directive cites this. Its purpose: convert taste into an enforceable standard so the product reads as a finished institutional artifact, not rough work. Where a component disagrees with this doc, the component is wrong.

**Principle 0 — grid-structured external, dynamic internal.** Fixed frames; only data inside them changes. Governs layout AND controls (a slider track never resizes with its value; a card never reflows with its number).

- **Categorical (NOMINAL) palette — LAW (ratified KC 2026-07-25; binds every categorical layer the site adds).** Nominal categories (amenity type, zoning family, any qualitative axis) take a QUALITATIVE, hue-separated palette — **never a sequential/spectral ramp**, which asserts an order nominal data does not have (the retired amenity Vivid-10 spectral ramp + its three-adjacent-greens were the D4/D7 defect). The rule, five parts: **(1)** one palette, **`QUALITATIVE_12`** (in `amenityPointStyle.js`): `#ff3d6e #ff8c1a #ffc300 #a3e635 #22c55e #00c9a7 #22c1ff #5b7cff #a855f7 #ff45cf #8b5a2b #0e7490` — crimson · orange · gold · lime · green · teal · sky · blue · violet · magenta · brown · petrol; **verified min pairwise CIE76 ΔE 33.8** (no two adjacent-confusable; ONE green only), **min contrast vs the casing `#141018` 3.22:1** (WCAG 1.4.11). **(2)** assign by **count descending** (the commonest category gets the most-distinct index-0 hue). **(3)** a **residual class** (null / Unknown / Non-Networked / Other / …) renders **grey `#8b98a7` and sorts LAST** — it is NOT a palette hue (D5); the residual token set is encoded backend so it cannot drift. **(4)** the palette caps at **12 hues** (the ~12-hue discrimination ceiling); past **12 REAL** classes, the tail collapses to a single grey **Other** (D6/D7), so the ceiling is never exceeded — and a collapse only ever fires above 12 (an 11-class layer shows in full). **(5)** display labels are tidied backend (no raw DB value like `SHELL_RECHARGE` in a legend, D9). Contrast is carried by the dark casing, so the hues stay vivid. The `--pa-*`/BC Vivid-10 palettes are a **separate** system (that section's own law); this is the amenity/categorical law.
- **Glyph channel — LAW (revised KC 2026-07-27; supersedes the withdrawn glyph-carries-category rule).** A categorical layer may carry a cream Maki GLYPH per point. **An icon set is a GLYPH source, NEVER a palette source** — Maki supplies shapes; colour always comes from `QUALITATIVE_12` above. Two placements: **(a)** where a category axis has natural iconography, **COLOUR AND GLYPH BOTH carry it** — redundant encoding measurably beats either channel alone (≈88% vs 66% colour-only vs 58% shape-only) and survives colour-vision deficiency + the overview zoom where glyphs drop but colour does not; so the 12-hue ceiling **relaxes** (a confusable pair is disambiguated by its glyph), and a >12-category layer no longer needs a collapse. **(b)** Where a category has no iconography (an age band, a brand), colour carries the category and ONE layer glyph identifies the layer. **Layer identity:** every layer carries its OWN identity hue from `QUALITATIVE_12` — with the exclusive selector the disc colour is what tells the reader which layer they are on — used for the **selector chip + cluster discs**; keep clear of the basemap water-blue and park-green bands, and of the warm-cream band (**no orange** — hue-adjacent to the ground, a figure-ground failure). For a colour+glyph layer the identity hue = the **dominant family**, not a 12th colour. **Semantic hue adjacency:** within a multi-hue categorical layer, any two categories that must sit close in hue belong to the same KIND (a family); a lightness/saturation step separates members within a family; the glyph names the specific thing — so no confusable hue-pair is cross-kind (assign glyph↔hue deliberately and verify on screen, not in the registry — a redundant colour+shape pairing does not always keep two individually-strong choices strong in combination). Residual grey + last stands. Glyphs are **cream, non-SDF** (the disc carries colour; SDF's small-size sharpness penalty is not needed), **`icon-allow-overlap:true`** (else the disc draws bare — the most likely defect), appearing from mid zoom (a glyph is mud at overview) — a SPARSE layer may opt into a larger "prominent" disc that shows the glyph from the home overview. Per-glyph `icon-size`/`icon-offset`/threshold tuning + a Maki substitution are allowed (geometry, not colour) and recorded in the style module. Vendored: **Maki 8.2.0, CC0** (`website/public/icons/`; README records source + licence).
- **Categorical POLYGON-FILL palette — LAW v3 (2026-07-29, optical pass 4; supersedes the v1 convention-hue/pattern law and the v2 register-tier law; first instance: the zoning family fill).** `QUALITATIVE_12` still does not apply to area fills (ratified for small marks on the dark casing). The polygon law, four parts: **(1) Hues are DERIVED, not chosen:** the Glasbey method (greedy farthest-point under a CVD-aware distance — the minimum of normal / deuteranopia / protanopia CIE76), **seeded with GTA-BRIGHT 5** so every polygon palette provably extends the site's vivid register; ≥25° pairwise hue spacing (the generalised no-third-green anti-grouping rule); a hard chroma floor (zoning: C\*≥46, the seed's own minimum — "no greys, no dull shades" as a number, not a judgement). Derivations are one-shot scripts under the section's `_oneshot/`, frozen after use — output hexes are committed into the style module. **LBCS/planning convention is RETIRED as the hue source** — on an exploration instrument hue's job is discrimination; the legend and readout carry the meaning. **(2) LIGHTNESS carries AREA:** three bands (zoning: A L\*≈85 for the two ≥30%-area families; B L\*≈67 mid; C L\*≈54 deep + saturated for the sub-2% figures); cross-band pairs separate on two channels, which is the mitigation for running ten hues near the discrimination ceiling. **(3) The non-hue governance clause is RETIRED** after failing in two forms: patterns asserted figure weight at zooms that could not resolve them (v1), and near-neutral bases collapsed into the ground register (v2). Governance families take real hues at full chroma; the governance distinction is carried by the readout in words. **(4) HIGHLIGHT is a separate channel, not more colour:** hover/selection ride feature-state — a lightness lift (hue + chroma held) plus an ACHROMATIC-EXTREME casing (near-white preview, near-black `#141018`-precedent commitment). **The no-greys rule governs DATA FILLS; casings and chrome are a separate register and always were.** Scope: side by side with the point law — supersedes nothing for points.
- **In-fill label rule — text printed INSIDE a categorical fill (2026-07-31, zoning legend strip; binds any section's future in-fill labels).** Where a label — a percentage, a count, a name — is printed INSIDE a coloured fill, its ink is DERIVED from that fill's lightness by **ONE measured threshold and EXACTLY two tokens, applied uniformly** (no third case, no per-family override): compute the fill's **WCAG relative luminance L**; **L > 0.42 → dark-on-light `#2a2621`** (= `--label-ink`, the map's dark ink), **L ≤ 0.42 → light-on-dark `#faf6ec`**. A single fixed ink fails at one end of a banded palette (dark text dies on the deep fills, light on the pale ones); the derived pair holds across the whole range. `0.42` is a design constant at the palette's midpoint gap — every zoning family clears it with margin (the nearest, Industrial / Direct Control / Civic at L≈0.304, sit 0.116 **below** → light; Residential at L≈0.62 is the nearest **above** → dark). These two are the achromatic in-fill register (kin to the map label polarity, §5), sanctioned literals under the no-greys carve-out. **Precondition:** an in-fill label may appear only where the fill is wide/tall enough to hold it — a legend chip that prints its value must reserve a text FLOOR (see the legend-strip proportional-floor, §5). If a section ever removes the printed value from a fill, this rule and the floor go with it.

## 2. Typography rules (written down = enforceable)
- **Font:** house sans stack (Inter/system). Sans only. No serifs in chrome.
- **Capitalization — THE RULE (amended 2026-07-13, recurring drift ends here):** Title Case with **lowercase minor words**. Capitalize every word EXCEPT minor connecting words when they fall **mid-phrase**: articles (*a, an, the*), coordinating conjunctions (*and, but, or, nor*), short prepositions ≤4 letters (*of, in, on, to, by, as, at, off, per, over*), and *vs*. **Always capitalize the FIRST and LAST word**, regardless. Acronyms stay upper (YoY, m²); a unit in parens keeps its own case (`(%)`, `(m²)`). No sentence case, no ALL-CAPS, no arbitrary lowercase in chrome. Applies to metric buttons, legend titles, table headers, KPI labels, console headers, dropdown items, buttons — everything the user reads that isn't data. Exact transformations (apply verbatim):

## 4. Contrast floor (enforced; legal, not just polish)
- Text vs its surface: **≥4.5:1** (`--tx-mut` on `--shell` must pass; the old muted grey did NOT).
- UI/graphical elements (borders, chart strokes, control affordances): **≥3:1**.
- Map label text vs halo: **≥4.5:1** (`--label-ink` on `--map-cream` ≈13:1 ✓).
- Disabled/inert states may drop below, but stay readable (opacity, not invisibility).
- Test every new colour pair before commit. This is a WCAG 2.2 AA floor; for an institutional (UAlberta) artifact it is a requirement.
- **Map POINT SYMBOLS conform via WCAG 1.4.11 Non-text Contrast (3:1), NOT the 4.5:1 text floor (2026-07-24, FLAGGED for KC/Olivia ratification).** The 4.5:1 line above is **1.4.3 Contrast (Minimum)** — a **text** floor; it does not apply to point/graphical symbols, which fall under **1.4.11 Non-text Contrast at 3:1**. The BC View-1/View-2 vivid dots conform against the symbol's **dark casing `#141018`** as the immediate-background boundary: **casing vs the map grounds 6.4–16.7:1** (cream/pink/grey) and **each vivid fill vs its casing 5.1–12.7:1** — every luminance transition in the `fill → casing → ground` stack clears its applicable floor. **A naive fill-vs-ground reading returning <4.5:1 (or <3:1) has this documented rationale** and is an intentional, standards-correct choice, not a silent miss: no saturated hue can clear 4.5:1 against a mid-tone warm ground (measured max ~2.9:1), so the casing is the correct cartographic solution — the ground stays warm, the dots stay vivid. **The View-2 FAINT (non-significant) baseline is classified as INCIDENTAL / inactive context** (the dispersed baseline is read as pattern, not a value read precisely — WCAG exempts incidental elements from the contrast floor); it is deliberately subordinate (volume-scaled opacity 0.12–0.4, smaller than significant), so it carries no non-text-contrast obligation. **§5 (2026-07-24): the faint baseline now ALSO carries the shared dark casing** — a thinner stroke (`FAINT_STROKE_W`) whose `circle-stroke-opacity` is TRACKED to the fill's volume-scaled opacity, so both point views share one dark casing while faint stays subordinate; the incidental classification is unchanged (the casing only crisps its edge, it does not promote faint to an active read). **Point-casing token is shared: `POINT_CASING` (`#141018`), View 1 (halo) + View 2 (significant stroke + faint stroke) — one token, no second introduced.**
- **KNOWN FOLLOW-UP (logged, not built) — colourblind redundancy for View-1's ten sector hues (WCAG 1.4.1 Use of Colour).** `VIVID_10` at min ΔE 30 is strong *perceptual* separation, but ΔE is not CVD-safety: ten vivid hues very likely contain a red-green collision under common colour-vision deficiency, which engages 1.4.1 (colour must not be the sole information carrier). A later pass must add a non-colour channel for View-1 sectors — **shape redundancy, guaranteed label-reachability (hover/select already names the sector), or a CVD-safe sub-palette**. View-2's five hues (blue/teal/magenta/green/orange) are lower risk. Logged here; not a blocker for shipping the vibrant palettes.
- **SANCTIONED DEPENDENCY — KaTeX `0.16.x` (2026-07-24), math-rendering only.** Renders the LCLQ formula + `cases` interpretation in the Business Census View-2 **method box** (`LclqMethodBox.jsx`). Rendered **once at mount** (`katex.render`, `displayMode`), **MathML output ON** (default `htmlAndMathml` = visual HTML + screen-reader MathML — accessible). The formula is transcribed from KC's R implementation, not reconstructed. Its stylesheet (`katex/dist/katex.min.css`) is imported by that one component. New stacks stay otherwise closed (§9 CLAUDE.md: React + Vite + MapLibre + Recharts-free hand-rolled charts + `@tanstack/react-table`); KaTeX is added **only** for math typesetting, nowhere else.

## 5. Map/cartography law
- **Labels:** `--label-ink` text + `--map-cream` halo, halo width ~1.5px (as narrow as stays legible — "effective but invisible"). The cream halo makes the label readable over ANY choropleth colour because the halo is the text's effective background.
- **Collision:** our centroid labels and basemap labels share ONE collision index (adjacent layer order, `text-allow-overlap:false`) so they never overprint each other. Hover/selected label is the ONE exception (`allow-overlap:true`) — the pointed-at neighbourhood always names itself.
- **Density by zoom:** major neighbourhoods only ≤~z11 → mid tier ~z12.5 → all ~z14. The overview breathes; the table holds the exhaustive list.
- **Building harmony:** building footprints blend to luminosity (hue drops out → tonal texture) so they never clash with the active ramp (sequential OR diverging). Colour-only; no data. *(Scope: this is the CHOROPLETH-ramp rule — buildings over a sequential/diverging fill, PA/DU/BC. On a THEMATIC/categorical map the reference-building carve-out below governs, which ratifies zoning's height-tiered translucent achromatic fill.)*
- **No internal debris on the map:** parcel counts, suppression flags, and other internal fields never render as map labels. They live in the table/detail.
- **Thematic-map reference law (2026-07-29, first instance: Zoning).** On a thematic map the base provides geographic context and must VISIBLY RECEDE — the data fill is the figure; no reference feature may compete with it. Reference features are a designed system, not leftovers: roads disclose progressively by tier (freeway always · arterial z≥11 · collector z≥13 · local z≥15 — locals never render at district zoom), every stroke sits on an explicit LINE-WEIGHT LADDER of named constants (zoning: freeway → arterial → family boundary → collector → local → parcel → building outline; no two rungs equal at any zoom, or the map reads as mesh), reference colour is a warm near-neutral in register (never UI white; casing, where used, is darker than its road — recession, not glow), rail is one thin reference line, buildings are ACHROMATIC REFERENCE TEXTURE at parcel zoom (default outline-only; the ratified zoning form is a translucent height-tiered fill — carve-out below), and labels use POLARITY (dark text / light halo, ≤¼-font-size width, light blur) rather than hoping a halo colour blends with every fill. Where legibility contends, the ladder yields from the bottom: parcel first, then buildings — the primary (family/zone) boundary never gives way.
- **Reference buildings on a thematic map — the building-fill carve-out (amended 2026-07-30; ratifies KC's zoning pass 8, resolving the doc↔code conflict the DESIGN_SYSTEM sweep surfaced).** The reference-building law above defaults to *outline-only engraving*, but the RATIFIED zoning form — the law's only instance — is a height-tiered TRANSLUCENT fill, and it is **compliant, not a deviation**. The treatment: a warm charcoal-umber (`BUILDING_TONES` = `#4a443c` / `#3a342c` / `#2b2620`, three tone steps by `render_height` — <15 m · 15–40 m · ≥40 m, taller = darker), a hue deliberately **OUT of the family palette's colour space** so it can never be read as a zone colour; zoom-graded opacity (z14 `0.10` → z17 `0.36`) so the **zone fill reads THROUGH** the building — a building reads as *sitting in* its zone, not covering it; a slightly-darker outline (`rgba(28,23,18,0.55)`); and a faint offset cast-shadow (`zoning-building-shadow`, z≥15, 1.5 px viewport translate, opacity `0.06`→`0.16`) drawn *beneath* for physical presence with **no extrusion, blend mode, or glow**. `minzoom 14` makes the typology self-select — large footprints survive, small ones go sub-pixel and vanish (no size filter). **Why this satisfies the law:** buildings are the REFERENCE register, and §1.4's no-greys rule + this section's "colour-only, no data" clause govern the **FIGURE's palette** (the family fills / the choropleth ramp), NOT the achromatic reference layer — a receding, hue-less, translucent building competes with nothing. Height-as-tone is a reference *second channel* (a hillshade, not a data ramp). It still YIELDS first when legibility contends (per the ladder above, after parcel) and never at the expense of the family/zone boundary. The default outline-only form stays available to a future thematic map; **either is compliant** so long as the building recedes, stays achromatic + out-of-palette, and never competes with the figure.
- **Categorical-map reading surfaces — the zoning legend strip + two-stage rail (2026-07-30, zoning v1.20; the pattern a future categorical polygon map inherits).** A categorical polygon map has no ramp and no data console, so it reads through two surfaces. **(1) The proportional legend strip** — bottom-docked on the dark console glass (§1.1), a single AREA band of chips sized **MIN + (area share × remaining)** — **proportional ABOVE A TEXT FLOOR, not strictly proportional** (2026-07-31) — ordered area-descending; each chip prints its share INSIDE itself, the ink by the §1.4 in-fill label rule. **The floor's tradeoff, stated:** strict proportionality can't hold the smallest family (0.8% is a few pixels), so every chip reserves the width of the widest percentage string + padding (zoning: 48 px at 11 px/600) and the remainder is distributed by share — the top families shrink, the bottom four grow, and every chip clears its own number. This distortion is acceptable ONLY because **the true value is printed inside every chip — the number corrects the pixel**; if the printed value were ever removed, the floor must go with it (and the bar returns to strictly proportional). Family names sit below, **measured** (a name renders only where its chip holds it whole — hide-not-drift, never shrink/rotate/truncate; a long ratified name like "Industrial and Employment" can exceed its own proportional chip and hide, the readout then supplying it); a hover/isolate/select **readout** replaces the labels with the true numbers as one sentence. Interaction lives in a transparent hit-button layer, and the visual band is `pointer-events:none` (so an emphasised chip's z-index cannot steal the pointer — the loop bug); the costly map preview is **debounced to the cursor's rest** so a fast sweep does not cascade full-layer repaints. **(2) The HIGHLIGHT is ABSOLUTE, not relative** (the §1.4 polygon HIGHLIGHT law applied to chips): the focused chip — hover / isolate / reciprocal-select, ONE treatment — takes a TWO-TONE achromatic casing (light `#faf6ec` + near-black `#141018`) plus a small lift, never touching the fill, so it holds at BOTH lightness extremes where dimming-the-others fails on a pale or dark chip. **(3) The two-stage right rail** — ABSENT at rest; stage 1 (hover) = swatch · family · neighbourhood; stage 2 (pinned) = the byte-identical header expands DOWNWARD (nothing shifts under the cursor) plus the zone code large in mono (the one string the reader quotes), description, dc2 sub-area only when populated, area, family share, and a copy-link permalink; three-way dismissal (✕ / Esc / click-outside). Selection and isolate are MUTUALLY EXCLUSIVE in both directions.
- **Categorical legend TABLE — column colour tiers (2026-07-31; binds any section's legend table).** A legend table (zoning: swatch · family · zones · area) is a fixed-column grid with a Total row under a foot rule, rows ordered by the map-encoded measure DESCENDING. Its column text follows a MEANING-tied three-tier rule, not a uniform grey: **the family NAME and the map-ENCODED measure (here AREA %) are PRIMARY (`--pa-ink`); the supporting COUNT is SECONDARY (`--pa-mut`); the column HEADERS and the TOTAL row are MUTED (`--pa-mut`).** Area is primary **because it is what the map fill encodes** — it drives the legend-strip widths and the row order; giving the count equal weight would present two competing rankings, so the count recedes. Numeric columns are right-aligned in `tabular-nums` at fixed widths so digits align vertically, and there is **NO interpunct — the column boundary is the separator**. The Total row doubles as the completeness check (the shares sum to 100%). Rows are the SAME click-to-isolate control as the section's other legend surface (the strip), sharing one `isolated` state so isolating from either updates both. A family name too long for its column ellipsizes with a `title`/aria full-name (a table, unlike the strip, may ellipsize — the swatch + tooltip + strip carry identity).
- **KPI card = square-ish tile:** label (top) → big value (centre) → city + delta (footer row). Vertical stack kills mid-rectangle dead space. Grid of tiles in the rail, not wide rectangles. `--card` surface, `--hair` border.
- **Two-lens comparison (CONDO card):** distinguish the two questions explicitly — (a) vs-city share comparison (primary line, pp delta, `--city` baseline) and (b) within-neighbourhood condo-stripped view (secondary block under an `excluding condos:` label). Never conflate.
- **Selection:** one meaning, two surface-appropriate encodings — the **map** boundary is `--pa-selection-outline` violet (top-of-stack, distinct from the ramp), the **table/rail** accent is `--sel` coral (P4). Both read as "selected."
- **Metric chips (left rail):** each carries a leading glyph — one inline stroke SVG per metric (24×24 viewBox, `stroke="currentColor"`, `aria-hidden`; the label carries the accessible name), sized ~14px to sit with the chip text. The glyph inherits the chip ink, so it greens with the active chip — **no per-metric colour** (the green border is the only selected signal). Glyph set lives in `choroplethStyle.js` METRICS (data-driven, one place). Icons appear on the rail chips ONLY — not the console-header re-home, map, legend, or table (P5).
- **City baseline:** `--city` blue on every surface, labelled with the ACTIVE CITY NAME (e.g. "Edmonton"), read dynamically — never the literal word "city," never a hardcoded "Edmonton."

It carries `aria-pressed` so the state is real for a screen reader too, not merely visible. Icon-only, so every one carries an `aria-label` (the accessible name) and a target larger than its glyph; decorative marks are `aria-hidden`. **Recentre is NOT geolocation** — it fits the selection, else the HOME camera preset; no geolocation exists in this app, so the glyph is a fit-frame (`focus`), never a GPS crosshair. **Its name is state-aware, its shape is not (Option C, ratified 2026-07-15):** the label reads `Fit to selection` when a selection exists and `Return to home view` when none, while the silhouette never changes. No single conventional metaphor covers both actions, and a *swapping* glyph would be worse — people learn a button by its shape, and a shape that moves is harder to learn. The accessible name is mandatory on an icon-only control anyway, so the precision is free and nothing is misstated. **`.pa-detail`'s `top` is DERIVED from this stack's height** — add or remove a control and you must re-derive it (adding the "i" moved it 208px → 250px).

- **Popover-as-documentation (2026-07-15).** Map help opens from the rail's "i" — a map-level utility belongs on the map, not as a text link in a column footer. The panel is a **visual index**: one line per interaction, each carrying **its own control's glyph** from the same family, so tip→control is instant wayfinding rather than decoration. Keys are **key-caps** (`⇧`, `T`), not spelled out — the reader is hunting a physical key. **Every row is ONE two-column grid (2026-07-16, ratified): a fixed icon gutter + text at a shared left edge** (Principle 0) — all eight rows align, and multi-line tips wrap to the text edge, never back under the gutter. Distinct actions get **distinct lines** (the two clears are two undos). Where a row also teaches a real console button, that button rides **inline in the sentence** as its subject while a shared eraser icon holds the gutter — so a pill never becomes the aligning element (a full-width pill in the gutter is what broke the grid before). Order is **gestures first** (scroll · click · shift-drag), then chrome (console · search · sliders), then the clears; `Scroll to Zoom` leads because it needs no teaching. **The §6 honesty block is NOT a tip:** the selection-aggregate disclosure sits at the foot, outside the index — **BULLETED** (Mean parcel-weighted/exact · Median & YoY neighbourhood-weighted estimates ≈) so the asymmetry is the point, muted tier, never stripped. **No em dashes in the rendered card** (ratified): bullets are short complete sentences; rows use their icon/pill as the subject, no connector needed. **The "i" is the SINGLE affordance — there is no `×` (ratified 2026-07-15):** click to open, click to close, one control and one mental model. `Esc` also closes (keyboard convention + a11y: a keyboard user must not have to tab to the "i" to escape) — that is not a second visual control, just not trapping people. **There is deliberately NO click-outside dismissal:** on a map, clicking empty space IS exploration, so "standard popover behaviour" would kill the card during the very practice it exists to accompany. Do not add it back.
- **The introductory usage card = the popover's first life (ratified 2026-07-15). SUPERSEDES the separate first-run hint, which is deleted.** A hint teaching `⇧ + drag` *beside* a card teaching the same gesture is two things at once — the bombarding the research warns against. The card IS the introduction.
  - **READ-AND-TRY.** It auto-opens on a first visit and **survives all exploration** — pan, zoom, scroll, clicks that hit nothing, slider drags. Those are orientation, and killing the card mid-orientation is the failure mode.
  - **It dismisses on the FIRST SUCCESSFUL SELECTION, and nothing else** — a neighbourhood click or a completed area-select (both land in `selectedIds`, which is why the trigger watches the selection rather than either gesture). A selection is the terminal act of the loop the card teaches, and the exact moment the InfoRail populates and the console becomes meaningful — so attention *should* move to the data. **The handoff:** selection → card closes → InfoRail populates → the glow-off "i" is the visible record of where the card went. It doesn't vanish; it becomes the "i".
  - **Why the three obvious alternatives are all wrong** (do not reintroduce any of them): a **timer** yanks it away mid-read (NN/g: dismissal is user-controlled; Chameleon: at the wrong trigger 38% dismiss inside four seconds — *the trigger is what changes, not the design*); **dismiss-on-any-interaction** kills it during exploration; **click-outside** is the same mistake wearing a convention's clothes.
  - **Dismissal is PERMANENT and ONE-WAY** — persisted; never auto-opens again on any later visit; **Clear Selection does not resurrect it** (re-teaching an introduced user is the auto-resurface the research forbids). Only the "i" reopens it, forever. After that recall the card is a manual reference, so a later selection does NOT close it.
  - **It must not obstruct the practice area** — anchored under the "i", it leaves 914px (61% of the canvas) clear of the left column for the shift+drag it teaches. Verify this if it is ever repositioned.
  - Storage is wrapped **fail-soft**: it *throws* in Safari private mode, and a card must never cost the page. On a read failure, show it — when we cannot know, the honest default is to introduce the map.

The search is TanStack's `globalFilter`, a channel apart from `columnFilters`, and that split trapped users: a search held the table at one row while the button — counting only columnFilters — sat disabled, and the peek closes on select so the input that set it was off-screen. The replica is the index principle taken literally: the tip shows the control you will go and look for. The two blocks below the tips are PROSE, never compressed into tip lines: the **aggregate-methodology** hedge (a §6 honesty label → **muted** tier) and the **source citation** (currency + naming change → **primary** tier per the §6 carve-out above, `.pa-box-cite`).

  - **Duochrome rim construction (LOCKED — 2026-07-14 bug fix).** The pearl rim is a **mask + pseudo-element** ring (`::after { inset:0; border-radius:inherit; padding:1px; background:var(--accent-rim-image); mask: <solid> content-box exclude, <solid> }`) — NOT `border-image` (which ignores `border-radius` → rectangular seams on rounded pills, Mozilla-confirmed) and NOT the two-background-layer trick (which needs an opaque body — ours is glass-transparent over the map). The `--accent-duochrome` sweep is a **cyclic** `repeating-linear-gradient` whose first and last colour MATCH (`#10464a`…`#10464a`), else the repeat boundary is a hard jump = a mid-run seam (the image-3 bug). Fixed ~132px period so the flip reads at one scale on long and short elements. No hard colour stops (all gradual). **Luminance-flat rule (checkable law):** only HUE travels (teal→cyan→gold-green); the sweep stays even in luminance (all stops L≈0.53–0.62) — a lit edge whose colour travels, never a dark stop landing mid-run (a dark stop = the "warp/pinch" bug on long buttons). Do not reintroduce `border-image`, a non-cyclic sweep, or a dark stop.
