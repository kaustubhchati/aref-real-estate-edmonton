# DESIGN SYSTEM — AREF Open Data Centre (governing design law)

**Status:** Normative. The human-facing companion to `PA_MODE_CONTRACT.md`. Every future frontend directive cites this. Its purpose: convert taste into an enforceable standard so the product reads as a finished institutional artifact, not rough work. Where a component disagrees with this doc, the component is wrong.

**Principle 0 — grid-structured external, dynamic internal.** Fixed frames; only data inside them changes. Governs layout AND controls (a slider track never resizes with its value; a card never reflows with its number).

### 1.3 Colour — semantic roles (the ONLY places colour carries meaning)
**Governing principle (Option 1, ratified 2026-07-14): COOL = interactive chrome, WARM = data.** Two colour systems: the DATA hues below (warm/blue/violet, each a fixed meaning) and the ONE interactive-accent (teal, cool). Green is DATA-ONLY — no chrome may use it.
- `--data-up: #4ade80` — growth/increase (YoY positive, pp positive)
- `--data-down: #f88b6b` — decline/decrease (YoY negative, pp negative)
- `--city: #60a5fa` — the comparison-baseline (active city) datum, EVERYWHERE (line + numbers). Dashed line + blue = redundant encoding (colour-blind safe)
- `--sel: #e8734a` — selection accent on the **TABLE + RAIL** surfaces (the map boundary uses `--pa-selection-outline`)
- `--pa-selection-outline: #8b5cf6` — the **MAP** selection boundary stroke; violet, reserved distinct from the sequential/diverging ramps, `--data-up` green, `--data-down`/`--sel` coral, and `--city` blue. Violet appears nowhere in the basemap or any data ramp, so it reads unambiguously as "not data." Map-only (P4): the ramp collision it solves exists only on the choropleth; the table has no fill behind its rows, so table/rail selection stays `--sel` coral. MapLibre paint can't read CSS vars → `choroplethStyle.js` mirrors this literal.
- **`--accent-teal: #2dd4bf` — the interactive-accent (CHROME, not data; 2026-07-14).** The ONE colour marking *interactive* controls: active metric-button / toggle text, slider value readouts (`--tx-read` = teal), slider fill / thumb ring / major-tick emphasis, focus rings. Delivered as a teal **rim + glow + text** on neutral active glass (not a flat fill), with a `font-weight` + light-rim non-colour cue (forced-colors → `Highlight`). Teal is cool (near-opposite the warm map; holds chroma through frost) and tuned into the GAP between `--city` blue (213°) and `--data-up` green (142°): teal at **172°** reads as neither city nor growth, and is clear of `--sel`/`--data-down` coral, `--pa-selection-outline` violet (258°), and YoY-indigo (229°). §4: teal ≥4.5:1 on the active body (5.0:1) and the dark tuning bay (9.6:1); readouts contained on the bay (≥7.9:1). Retires the warm C2° glow that blinded out over the warm map. It is the ONE saturated interactive mark (≤~10% of the field per 60-30-10); chrome *surfaces* still obey the ≤8% tonal ceiling (§1.1). *(An optional Layer-2 pearlescent rim/dome sheen — cool-family, edges only — is codified in §6 only if it ships.)*
- **Signed deltas (amended 2026-07-13): ALL signed deltas colour by sign** — `--data-up` (positive), `--data-down` (negative). `COLOUR_LEVEL_DELTAS=`**`true`**. The former level/rate distinction ("colour on levels editorializes; reserve it for rates" — NEUTRAL `--tx` on level deltas) is **retired**: a signed delta reads by direction regardless of whether it compares a level (median/mean/lot vs city) or a rate (YoY, condo pp). Both `%` and `pp` deltas colour; unit doesn't matter, sign does. **Zero is neutral `--tx`** (no sign → no colour). The `+`/`−` sign glyph is the colour-blind-safe redundant channel (colour reinforces the sign, never sole-encodes it — §4). The **city baseline stays `--city` blue everywhere** (a reference datum, not a delta): the sign-colour applies to the *delta only*, never the baseline or the neighbourhood value (three distinct roles → three treatments: value `--tx` white · baseline `--city` blue · delta signed).

**THE ICON FAMILY IS LUCIDE (ratified 2026-07-15).** ONE open-licensed set dresses the whole rail (search · zoom ± · fullscreen · recentre · info) **and** the tips index — no MapLibre defaults, no hand-drawn glyphs, no mixed sources. The previous "Feather-style" marks were in-house approximations and are **all replaced**.
- **Source + licence.** Lucide 1.24.0, **ISC** (not MIT — the brief said MIT; the package ships ISC). ISC requires the notice travel with the copies, so it is reproduced in `mapIcons.js`, which also names the upstream icon behind every constant (`lucide: map-pin-search`, …) so any glyph is checkable against source.
- **Vendored, not installed.** §9 fixes the stack; an icon package is a new dependency, copied open-licensed artwork is not.
- **Why not Maki (the brief's lead candidate): it cannot dress this rail.** Maki is a POI/marker set — no zoom, fullscreen, fit-bounds or info glyph — so the rail could not be one Maki family, and mixing is what the brief forbids. Material Symbols (Apache-2.0) covers it but is a filled/variable-font language; adopting it means abandoning the stroke chassis. Lucide's spec **already is** ours: 24 viewBox · fill none · `currentColor` · stroke-2 · round caps/joins, so it drops onto the existing chassis with teal-on-interaction intact.
- **IP guard.** Google's **Maps product chrome** is brand-licensed and is never copied; its *conventions* (+/− zoom, corner-arrows fullscreen, fit-frame recentre) are not ownable and are what we take. (Google's Material Symbols *library* is separately open — the Maps UI assets are not.) `crosshair` / `locate-fixed` exist in the family and are deliberately unused: they mean "locate ME", and this map never geolocates.
- **Two mechanisms, one family, on purpose.** Zoom/fullscreen/shrink are MapLibre-OWNED DOM (it toggles their state classes), so their glyphs are CSS data-URIs **generated from the same `mapIcons.js` constants**; CSS cannot read JS. Taking those buttons off MapLibre to unify the mechanism would mean reimplementing the fullscreen API and the zoom-limit disabled state — a rewrite of a working core for a cosmetic win. Change a glyph in `mapIcons.js`, regenerate the CSS.
- PA-added controls inherit the 30px slot + full state set by emitting MapLibre's own markup (`makeIconButtonControl`), never by hand-rolling a button — hand-rolling is how `.pa-search-peek-btn` came to duplicate the rail by hand.

**Silhouette-first, and test at 18px (§1.3).** A glyph must say what it does by SHAPE alone — no colour, no tooltip. §1.3 spends colour on meaning, so decorative icon hue would collide with a reserved role or invent one; teal-on-interaction IS the icon colour and means "interactive". **Judge every glyph at its rendered size, never zoomed in — and reject there.** Two worked examples, both caught at 18px and not on the drawing board: a magnifier over a folded **map** collapsed into a blob (the fold's strokes crossed the lens) → replaced by Lucide `map-pin-search`, a pin with a lens; and Lucide `maximize`/`minimize` (corner brackets) **collided with `focus`** — near-identical silhouettes two slots apart on the same rail → fullscreen took the arrow pair `expand`/`shrink` instead. **Adjacency is part of the test:** a glyph that reads alone can still fail beside its neighbour.

## 2. Typography rules (written down = enforceable)
- **Font:** house sans stack (Inter/system). Sans only. No serifs in chrome.
- **Capitalization — THE RULE (amended 2026-07-13, recurring drift ends here):** Title Case with **lowercase minor words**. Capitalize every word EXCEPT minor connecting words when they fall **mid-phrase**: articles (*a, an, the*), coordinating conjunctions (*and, but, or, nor*), short prepositions ≤4 letters (*of, in, on, to, by, as, at, off, per, over*), and *vs*. **Always capitalize the FIRST and LAST word**, regardless. Acronyms stay upper (YoY, m²); a unit in parens keeps its own case (`(%)`, `(m²)`). No sentence case, no ALL-CAPS, no arbitrary lowercase in chrome. Applies to metric buttons, legend titles, table headers, KPI labels, console headers, dropdown items, buttons — everything the user reads that isn't data. Exact transformations (apply verbatim):
  - Metric buttons (full labels; order = value → change → composition → structural): `Median Assessed Value` · `Mean Assessed Value` · `YoY Change (Log Pts)` · `Condominium (%)` · `Mean Lot Size (m²)`.
    - **The YoY chip uses the ACRONYM (amended 2026-07-15).** `Year over Year Change (Log Pts)` measured 217px inside a 207px chip and clipped its own closing bracket. `YoY` is an established acronym and this §'s rule already keeps acronyms upper, so the chip carries the short form: between the name and the unit, the unit is what earns the room — a chip that says "Year over Year" and hides its unit is the drift D7 ends.
    - **YoY's unit is LOG POINTS, not `%` (amended 2026-07-15).** The backend emits `log(median_now / median_prior) * 100` — a log change (`04_aggregate_historical.R:274`). It is NOT a percent, and the two diverge hard in the tail: ROSENTHAL 2014 is `159.7` log pts, which as a percent is **+393.8%**. The former `(%)` label was a knowingly-accepted approximation (`b3c8fb4`) whose stated bound the greenfield tail broke — see METHODOLOGY.md **D7**. **No `%` may appear on this metric anywhere**, and no `pp` on its deltas (a percentage point is the gap between two *percentages*; a log-point gap is log points). Notation is **`Log Pts`** everywhere — `Δln` is rejected, one notation only.
  - Legend title: matches the active metric verbatim (e.g. `Median Assessed Value`, `Condominium (%)`).
  - Table headers (SHORT tier — space-constrained; a deliberate separate tier from the full metric-button labels above): `Neighbourhood` · `Median` · `Mean` · `Lot m²` · `Built` · `% Condo` · `YoY (Log Pts)` · `Trend`. (The console-header metric chips use these short labels for the same space reason.) **`YoY (Log Pts)` carries its unit even in the short tier (amended 2026-07-15)**: a bare `YoY` invites the `%` the reader already assumes, which is exactly the drift D7 ends. The unit sits in the header so the CELLS stay bare signed numbers (`+7.3`, `−1.3`, `144.7`, tabular-nums) — stated once, not once per row. The range-slider label reads this same header, so the unit is stated once there too and its readout stays bare.
  - KPI labels: `Median` · `YoY (Log Pts)` · `Condo` · `Distribution` (+ honesty tags: `≈ Of Medians` — "Of" is the first word after the `≈` symbol so it stays capital; `Parcel-Weighted · Exact`; `Excluding Condos`).
    - **The YoY tile states its unit in the LABEL, not the value (2026-07-15).** Every other tile's unit is one glyph and rides the number (`$166k`, `100%`); `log pts` is seven characters and wrapped the tile's dominant value onto two lines in a 128px tile. So the label carries it and the three figures stay bare (`+10.2` · `Edmonton +6.5` · `+3.6`) — the same rule as the table header and the range-slider label. **The InfoRail is the one exception**: its triplet cells are ~70px and their labels are ROLES (`Value` / city / `Delta`), so there is nowhere to hoist the unit to and the numbers go bare there. That is safe only because the rail renders solely with the console DOWN, where the active metric chip and the legend both read `YoY Change (Log Pts)` on screen.
  - Console header scope: `All 407 Neighbourhoods` · `6 Neighbourhoods Selected` · `<Name>` (name as delivered).
  - Handle/affordances: **`Data Console`** · `Press T`. **Renamed 2026-07-15 (`Data Table` → `Data Console`, ratified):** the surface stopped being a table when it grew the KPI rail, the trend instrument, the distribution and the export — "table" named one pane of it. The rename is user-facing text only (handle title + accessible name); the `T` hotkey keys on the KEY, and no route, query-param or persisted state was ever keyed on the name, so nothing behavioural moves. **`Analyst View` is struck from this list, not renamed** — the recon found it is not a live string anywhere in `src`: the chip was removed in Fix A2, and only its own removal-comment still says the words. This list had been naming a control the UI does not render, which is precisely the drift §2 exists to end. (The `.dt-*` CSS/component names stay: internal, not user-facing, and churning them buys the reader nothing.)
  - Map labels follow the data's own casing (Title Case as delivered).
- **Numerals:** `font-variant-numeric: tabular-nums` on ALL numbers (tables, cards, readouts, sliders).
- **One number formatter, everywhere chrome-side:** compact — `$448k`, `≈$425k`, `611 m²`, `+7.3%`, `+72pp`. Full precision is Export's job ONLY. The `$448,000` vs `$731k` vs `≈$425,125` inconsistency is a defect.
- **Approximation mark `≈`** prefixes any median-of-medians or estimated aggregate. Never dropped.
- **Hierarchy by size, min 1 step:** adjacent hierarchy levels differ by ≥1 type step.

## 3. Essential vs non-essential (a rule, not a vibe)
Every displayed element must answer: *does this help the user decide?* If not, cut it. Current failures to remove: on-map `N=` count debris, stranded KPI-card mid-whitespace, duplicate trend readouts, verbose metric-name labels inside value triplets. Dual-encoding rule: label the essential (map key features get text labels alongside colour), suppress the rest. Less is more — especially on the map.

## 4. Contrast floor (enforced; legal, not just polish)
- Text vs its surface: **≥4.5:1** (`--tx-mut` on `--shell` must pass; the old muted grey did NOT).
- UI/graphical elements (borders, chart strokes, control affordances): **≥3:1**.
- Map label text vs halo: **≥4.5:1** (`--label-ink` on `--map-cream` ≈13:1 ✓).
- Disabled/inert states may drop below, but stay readable (opacity, not invisibility).
- Test every new colour pair before commit. This is a WCAG 2.2 AA floor; for an institutional (UAlberta) artifact it is a requirement.
- **Map POINT SYMBOLS conform via WCAG 1.4.11 Non-text Contrast (3:1), NOT the 4.5:1 text floor (2026-07-24, FLAGGED for KC/Olivia ratification).** The 4.5:1 line above is **1.4.3 Contrast (Minimum)** — a **text** floor; it does not apply to point/graphical symbols, which fall under **1.4.11 Non-text Contrast at 3:1**. The BC View-1/View-2 vivid dots conform against the symbol's **dark casing `#141018`** as the immediate-background boundary: **casing vs the map grounds 6.4–16.7:1** (cream/pink/grey) and **each vivid fill vs its casing 5.1–12.7:1** — every luminance transition in the `fill → casing → ground` stack clears its applicable floor. **A naive fill-vs-ground reading returning <4.5:1 (or <3:1) has this documented rationale** and is an intentional, standards-correct choice, not a silent miss: no saturated hue can clear 4.5:1 against a mid-tone warm ground (measured max ~2.9:1), so the casing is the correct cartographic solution — the ground stays warm, the dots stay vivid. **The View-2 FAINT (non-significant) baseline is classified as INCIDENTAL / inactive context** (the dispersed baseline is read as pattern, not a value read precisely — WCAG exempts incidental elements from the contrast floor); it is deliberately subordinate (volume-scaled opacity 0.12–0.4, smaller than significant), so it carries no non-text-contrast obligation. **§5 (2026-07-24): the faint baseline now ALSO carries the shared dark casing** — a thinner stroke (`FAINT_STROKE_W`) whose `circle-stroke-opacity` is TRACKED to the fill's volume-scaled opacity, so both point views share one dark casing while faint stays subordinate; the incidental classification is unchanged (the casing only crisps its edge, it does not promote faint to an active read). **Point-casing token is shared: `POINT_CASING` (`#141018`), View 1 (halo) + View 2 (significant stroke + faint stroke) — one token, no second introduced.**
- **KNOWN FOLLOW-UP (logged, not built) — colourblind redundancy for View-1's ten sector hues (WCAG 1.4.1 Use of Colour).** `VIVID_10` at min ΔE 30 is strong *perceptual* separation, but ΔE is not CVD-safety: ten vivid hues very likely contain a red-green collision under common colour-vision deficiency, which engages 1.4.1 (colour must not be the sole information carrier). A later pass must add a non-colour channel for View-1 sectors — **shape redundancy, guaranteed label-reachability (hover/select already names the sector), or a CVD-safe sub-palette**. View-2's five hues (blue/teal/magenta/green/orange) are lower risk. Logged here; not a blocker for shipping the vibrant palettes.
- **SANCTIONED DEPENDENCY — KaTeX `0.16.x` (2026-07-24), math-rendering only.** Renders the LCLQ formula + `cases` interpretation in the Business Census View-2 **method box** (`LclqMethodBox.jsx`). Rendered **once at mount** (`katex.render`, `displayMode`), **MathML output ON** (default `htmlAndMathml` = visual HTML + screen-reader MathML — accessible). The formula is transcribed from KC's R implementation, not reconstructed. Its stylesheet (`katex/dist/katex.min.css`) is imported by that one component. New stacks stay otherwise closed (§9 CLAUDE.md: React + Vite + MapLibre + Recharts-free hand-rolled charts + `@tanstack/react-table`); KaTeX is added **only** for math typesetting, nowhere else.

## 5. Map/cartography law
- **Labels:** `--label-ink` text + `--map-cream` halo, halo width ~1.5px (as narrow as stays legible — "effective but invisible"). The cream halo makes the label readable over ANY choropleth colour because the halo is the text's effective background.
- **Collision:** our centroid labels and basemap labels share ONE collision index (adjacent layer order, `text-allow-overlap:false`) so they never overprint each other. Hover/selected label is the ONE exception (`allow-overlap:true`) — the pointed-at neighbourhood always names itself.
- **Density by zoom:** major neighbourhoods only ≤~z11 → mid tier ~z12.5 → all ~z14. The overview breathes; the table holds the exhaustive list.
- **Building harmony:** building footprints blend to luminosity (hue drops out → tonal texture) so they never clash with the active ramp (sequential OR diverging). Colour-only; no data.
- **No internal debris on the map:** parcel counts, suppression flags, and other internal fields never render as map labels. They live in the table/detail.

## 6. Component patterns
- **KPI card = square-ish tile:** label (top) → big value (centre) → city + delta (footer row). Vertical stack kills mid-rectangle dead space. Grid of tiles in the rail, not wide rectangles. `--card` surface, `--hair` border.
- **Two-lens comparison (CONDO card):** distinguish the two questions explicitly — (a) vs-city share comparison (primary line, pp delta, `--city` baseline) and (b) within-neighbourhood condo-stripped view (secondary block under an `excluding condos:` label). Never conflate.
- **Selection:** one meaning, two surface-appropriate encodings — the **map** boundary is `--pa-selection-outline` violet (top-of-stack, distinct from the ramp), the **table/rail** accent is `--sel` coral (P4). Both read as "selected."
- **Metric chips (left rail):** each carries a leading glyph — one inline stroke SVG per metric (24×24 viewBox, `stroke="currentColor"`, `aria-hidden`; the label carries the accessible name), sized ~14px to sit with the chip text. The glyph inherits the chip ink, so it greens with the active chip — **no per-metric colour** (the green border is the only selected signal). Glyph set lives in `choroplethStyle.js` METRICS (data-driven, one place). Icons appear on the rail chips ONLY — not the console-header re-home, map, legend, or table (P5).
- **City baseline:** `--city` blue on every surface, labelled with the ACTIVE CITY NAME (e.g. "Edmonton"), read dynamically — never the literal word "city," never a hardcoded "Edmonton."
- **Honesty labels:** reportable/suppressed/excluded, exact/approx, aggregate formula tags — always shown, muted tier, never stripped. **Carve-out (KC, 2026-07-16):** a *source citation* (provenance / data-currency / naming-change line — e.g. the "i" popover's `Updated … / Naming Committee` line) is NOT an honesty label; it is a citation, and it reads at the **primary tier** (`--pa-ink`, via `.pa-box-cite`). The muted tier is reserved for the methodology *hedge* (the ≈/exact aggregate disclosure), which stays muted so it reads as a disclosure, not an instruction.
- **The right rail = the map's control stack (2026-07-15).** One chassis, one size (30px slot / 18px glyph), uniform fixed slots (Principle 0), stacked top-right in a fixed order: search · zoom ± · fullscreen · recentre · **info**. Every control carries the full state set — rest (neutral glass) → hover (rim-brighten + lift) → **active** → disabled (muted **in place**, slot reserved, e.g. zoom-in at max) → teal focus-visible, all reduced-motion-gated.
  - **ONE active scheme for the whole rail (ratified 2026-07-15): petrol body + pearl rim + teal glow** — and it is literally the `--accent-int-*` recipe the sidebar/console active buttons use (fill · border · specular · glow, plus the masked pearl `::after` as Layer 2). The rail is part of the same button system, not a look of its own. The controls differ in KIND, so the same material lands two ways: **toggles hold the glow while engaged** — the "i" (popover open), fullscreen (engaged; it also swaps to the inverse contract-arrows glyph, a real state change), search (input open) — while **momentary controls flash it on press** and fall back to rest — zoom ±, recentre — because they have no "on" state to hold.
  - **The "i"'s glow is LOAD-BEARING, not decoration.** The popover has no `×` (see below), so the glow is the only thing telling the reader where the close action lives. It carries `aria-pressed` so the state is real for a screen reader too, not merely visible. Icon-only, so every one carries an `aria-label` (the accessible name) and a target larger than its glyph; decorative marks are `aria-hidden`. **Recentre is NOT geolocation** — it fits the selection, else the HOME camera preset; no geolocation exists in this app, so the glyph is a fit-frame (`focus`), never a GPS crosshair. **Its name is state-aware, its shape is not (Option C, ratified 2026-07-15):** the label reads `Fit to selection` when a selection exists and `Return to home view` when none, while the silhouette never changes. No single conventional metaphor covers both actions, and a *swapping* glyph would be worse — people learn a button by its shape, and a shape that moves is harder to learn. The accessible name is mandatory on an icon-only control anyway, so the precision is free and nothing is misstated. **`.pa-detail`'s `top` is DERIVED from this stack's height** — add or remove a control and you must re-derive it (adding the "i" moved it 208px → 250px).
- **Attribution & licence standard (2026-07-16, ratified — governs every section).** Two SEPARATE info controls, never sharing a glyph: the top-right rail **usage "i"** (circled-i, *how to use this map*) and the bottom-right **data-symbol control** (Lucide `database`, *where the data came from*). The database control is a **quiet utility**, NOT a rail sibling — muted glyph that brightens on hover, a quiet teal-glyph active state (NOT the rail's petrol+pearl+glow), teal focus.
  - **Two surfaces (PA), because one MapLibre control can't be both:** an always-visible bottom **STRIP** and a click-open **PANEL**. **Strip = LINKS ONLY** — source · licence · © CARTO · © OpenStreetMap contributors — no prose (the disclaimer both overflowed into the centred Data Console handle AND is redundant inline). It is a MapLibre non-compact AttributionControl (CARTO/OSM ride in from the TileJSON automatically); solid dark bg so §4 holds over any basemap (muted punctuation 6.85:1, teal links 13.95:1); `max-width: calc(50vw − 110px)` so the right-anchored strip wraps upward instead of growing left into the centred handle (constant ~19px clearance, Principle 0). **Panel = the database control's popover** — the §6 HOME for the full record: source (link) · licence (link) · the **disclaimer** (moved here, never dropped) · © CARTO / © OpenStreetMap (linked). Sections without a console (BP/BC) keep the single compact control (disclaimer inline) — same theming, they inherit it.
  - **What is cited:** data source **City of Edmonton Open Data** (linked → `data.edmonton.ca`), its licence **Open Government Licence – City of Edmonton (Terms of Use v2.1)** (linked → the Terms URL), and the §6 **disclaimer** ("do not represent an official statement of City policy…"). The basemap credit **© CARTO, © OpenStreetMap contributors** is supplied verbatim by the CARTO TileJSON. All strings live once in `siteConfig` (`EDMONTON_OPEN_DATA` / `dataSource` / `mapAttribution` / `mapAttributionStrip` / `BASEMAP_SOURCES` / `BASEMAP_CREDIT`) — never hardcoded in a component.
  - **NO City of Edmonton logo, ever.** The Open Data Terms licence the *datasets only* and grant no right to the City's marks; importing the mark would also imply the endorsement the disclaimer disclaims. Text + Terms URL is the compliant form; if a mark is wanted, a generic glyph from the open icon family (never a trademark).
  - **CARTO/OSM wording is FIXED by licence** (CARTO terms + OSM ODbL) — keep the text + links verbatim; theme font/colour only, never iconify or abbreviate.
  - **The Terms URL must TRAVEL with every distribution** (the Terms' distribution clause). So each **export** carries source + Terms URL in a per-format-native way: CSV → the provenance `.txt` sidecar; GeoJSON → top-level `attribution` + `metadata`; PNG → an attribution strip **composited into the image** (the WebGL canvas has no DOM attribution, so a raw export would ship uncredited — a real gap, not a cosmetic one). The notice **passes the Terms through and adds no further restriction** (the Terms forbid it); export *data content* is unchanged — the notice is additive.
- **Popover-as-documentation (2026-07-15).** Map help opens from the rail's "i" — a map-level utility belongs on the map, not as a text link in a column footer. The panel is a **visual index**: one line per interaction, each carrying **its own control's glyph** from the same family, so tip→control is instant wayfinding rather than decoration. Keys are **key-caps** (`⇧`, `T`), not spelled out — the reader is hunting a physical key. **Every row is ONE two-column grid (2026-07-16, ratified): a fixed icon gutter + text at a shared left edge** (Principle 0) — all eight rows align, and multi-line tips wrap to the text edge, never back under the gutter. Distinct actions get **distinct lines** (the two clears are two undos). Where a row also teaches a real console button, that button rides **inline in the sentence** as its subject while a shared eraser icon holds the gutter — so a pill never becomes the aligning element (a full-width pill in the gutter is what broke the grid before). Order is **gestures first** (scroll · click · shift-drag), then chrome (console · search · sliders), then the clears; `Scroll to Zoom` leads because it needs no teaching. **The §6 honesty block is NOT a tip:** the selection-aggregate disclosure sits at the foot, outside the index — **BULLETED** (Mean parcel-weighted/exact · Median & YoY neighbourhood-weighted estimates ≈) so the asymmetry is the point, muted tier, never stripped. **No em dashes in the rendered card** (ratified): bullets are short complete sentences; rows use their icon/pill as the subject, no connector needed. **The "i" is the SINGLE affordance — there is no `×` (ratified 2026-07-15):** click to open, click to close, one control and one mental model. `Esc` also closes (keyboard convention + a11y: a keyboard user must not have to tab to the "i" to escape) — that is not a second visual control, just not trapping people. **There is deliberately NO click-outside dismissal:** on a map, clicking empty space IS exploration, so "standard popover behaviour" would kill the card during the very practice it exists to accompany. Do not add it back.
- **The introductory usage card = the popover's first life (ratified 2026-07-15). SUPERSEDES the separate first-run hint, which is deleted.** A hint teaching `⇧ + drag` *beside* a card teaching the same gesture is two things at once — the bombarding the research warns against. The card IS the introduction.
  - **READ-AND-TRY.** It auto-opens on a first visit and **survives all exploration** — pan, zoom, scroll, clicks that hit nothing, slider drags. Those are orientation, and killing the card mid-orientation is the failure mode.
  - **It dismisses on the FIRST SUCCESSFUL SELECTION, and nothing else** — a neighbourhood click or a completed area-select (both land in `selectedIds`, which is why the trigger watches the selection rather than either gesture). A selection is the terminal act of the loop the card teaches, and the exact moment the InfoRail populates and the console becomes meaningful — so attention *should* move to the data. **The handoff:** selection → card closes → InfoRail populates → the glow-off "i" is the visible record of where the card went. It doesn't vanish; it becomes the "i".
  - **Why the three obvious alternatives are all wrong** (do not reintroduce any of them): a **timer** yanks it away mid-read (NN/g: dismissal is user-controlled; Chameleon: at the wrong trigger 38% dismiss inside four seconds — *the trigger is what changes, not the design*); **dismiss-on-any-interaction** kills it during exploration; **click-outside** is the same mistake wearing a convention's clothes.
  - **Dismissal is PERMANENT and ONE-WAY** — persisted; never auto-opens again on any later visit; **Clear Selection does not resurrect it** (re-teaching an introduced user is the auto-resurface the research forbids). Only the "i" reopens it, forever. After that recall the card is a manual reference, so a later selection does NOT close it.
  - **It must not obstruct the practice area** — anchored under the "i", it leaves 914px (61% of the canvas) clear of the left column for the shift+drag it teaches. Verify this if it is ever repositioned.
  - Storage is wrapped **fail-soft**: it *throws* in Safari private mode, and a card must never cost the page. On a read failure, show it — when we cannot know, the honest default is to introduce the map.
- **Trend panel anatomy (2026-07-14):** header (metric title + top-right year·value readout) → main line chart (flex-grows to fill) → axis-end labels → **bottom legend (the series named ONCE, next to its line)**. The matched-sample **YoY·Matched bar strip was removed** (§3: an axis-less 3px bar didn't help the user decide; that YoY still lives in the table YoY column + the KPI YoY card). The series/scope name appears once (legend), never duplicated in the header.
- **About & tips popover = the canonical interaction reference.** Opens from the right rail's "i" (a map utility belongs on the map). ALL interactions documented once, Title Case, one line per tip, each led by its own control's glyph so the panel doubles as a visual index (gestures first, then chrome): `Scroll to Zoom` · `Click to Select a Neighbourhood` · `[⇧ shift] + [click] and drag to Select an Area` · `Press [T] for Data Console` · `Search to Find a Neighbourhood and Fly to It` · `Drag Slider Knobs to Select Year and Metric Range` · `[Clear filters] resets the Search, District and Range Filters` · `[Clear selection] deselects the Area`.
  - **`Clear filters` names the SEARCH (amended 2026-07-15).** It clears every narrowing the table applies — the District facet, the metric range, AND the search. The search is TanStack's `globalFilter`, a channel apart from `columnFilters`, and that split trapped users: a search held the table at one row while the button — counting only columnFilters — sat disabled, and the peek closes on select so the input that set it was off-screen. Every narrowing must have a visible clear; the button's coral enabled state is what advertises the way out. The tip names the search because a tip that under-describes its control is the drift §2 ends.
  - **`Select an Area` is the ratified term for shift+drag** (2026-07-15) — plain and spatially honest (the reader IS drawing an area), no collision with `District` or any data term, and it retires the jargon (`box-select`, `marquee`). **`Select an Area` / `Deselects the Area` are a MATCHED PAIR: one noun, and if the term changes BOTH change.**
  - **Keys and buttons are shown, not spelled.** `⇧ shift` is a LABELLED key-cap (a bare `⇧` teaches nothing to a reader who doesn't already know it); the click chip carries a pointer glyph; and the two clears show **scaled replicas of the real buttons in their enabled coral state** — not generic glyphs. The replica is the index principle taken literally: the tip shows the control you will go and look for. Those pills are NOT `aria-hidden` — they are text and they are the SUBJECT of their sentence (`Resets the Search, District and Range Filters` has no subject without them).
  - The inline `Press T` handle hint stays as the discoverable; the popover is the reference, not a replacement. The two blocks below the tips are PROSE, never compressed into tip lines: the **aggregate-methodology** hedge (a §6 honesty label → **muted** tier) and the **source citation** (currency + naming change → **primary** tier per the §6 carve-out above, `.pa-box-cite`).
- **Button standard — ONE language, every button on the page (2026-07-14, ratified).** EVERY button — sidebar metric chips, the city toggle, console utility (District, Export, both Clears), AND the right-side **map controls** (zoom ±, fullscreen, geolocate, reset, search) + the **scale bar** — shares one chassis + material + accent + fixed uniform slots. The console-button chassis below is that one shared geometry:
  - **Ratified chassis tokens** (the uniform geometry): `border-radius: var(--r-md)` (9px) · `padding: 4px 10px` · `font-size: var(--t-sm)` · `font-weight: 500` · `border: 1px solid var(--hair)` · `display: inline-flex; align-items: center; gap: 5px` · `white-space: nowrap`.   - **State layers** (the only thing a role adds on top of the chassis): metric chip → glass-key body (top-lit gradient + specular light-rim), `.active` = the DualSense material: **dark teal-petrol body** (`--accent-int-fill`) + **duochrome pearl rim** (`--accent-rim-image`, a thin metallic teal→cyan→gold-green edge-light; gold-green is metallic-highlight-only, never data-green) + **teal-white text** (`--accent-int-text`, T2 in the sidebar) + teal glow/`--accent-soft` spill + `font-weight:600` (the non-colour cue) — the sole selected signal, warm glow retired (2026-07-14, Option 1). **Both Clears → identical** (Fix 1): **enabled = coral** (`--sel`) outline + coral text ALWAYS; **disabled = muted grey**, inert in place (Principle 0 — the slot holds, never absent); District/Export → filled `--card` surface + a leading icon/caret. Focus rings on all controls (console + map) are **teal** (interactive), not the old coral.
  - **Duochrome rim construction (LOCKED — 2026-07-14 bug fix).** The pearl rim is a **mask + pseudo-element** ring (`::after { inset:0; border-radius:inherit; padding:1px; background:var(--accent-rim-image); mask: <solid> content-box exclude, <solid> }`) — NOT `border-image` (which ignores `border-radius` → rectangular seams on rounded pills, Mozilla-confirmed) and NOT the two-background-layer trick (which needs an opaque body — ours is glass-transparent over the map). The `--accent-duochrome` sweep is a **cyclic** `repeating-linear-gradient` whose first and last colour MATCH (`#10464a`…`#10464a`), else the repeat boundary is a hard jump = a mid-run seam (the image-3 bug). Fixed ~132px period so the flip reads at one scale on long and short elements. No hard colour stops (all gradual). **Luminance-flat rule (checkable law):** only HUE travels (teal→cyan→gold-green); the sweep stays even in luminance (all stops L≈0.53–0.62) — a lit edge whose colour travels, never a dark stop landing mid-run (a dark stop = the "warp/pinch" bug on long buttons). Do not reintroduce `border-image`, a non-cyclic sweep, or a dark stop.
  - **Interaction states (all buttons, uniform):** REST (neutral-glass key) · HOVER (rim-brighten + slight lift, transform-only, reduced-motion-gated) · PRESSED (depress) · SELECTED/on (active material — petrol + pearl + teal; e.g. fullscreen-toggled map control) · DISABLED (muted, in place).   - **Portaled menus flip at edges:** the District and Export menus are `position:fixed`, portaled to `<body>`. No teal on the drawer — green is the interactive/active colour. **Content:** renders `siteConfig.nav` in full — groups as labelled sections (icon + name, green header, icon via `currentColor`) with their pages beneath, top-level pages as plain links, each carrying the live/soon `StatusDot` (`Live` = green, `Soon` = muted `--chip-soft-*`); the active route is the green `--ua-green-soft` row (NavLink `end` on Home so `/` matches exactly). **Dismissal (three ways, per the §6 popover law):** the `×`, a scrim click, AND `Esc`. **A11y (the repo's first focus-trap):** `role="dialog"` + `aria-modal`; focus moves into the panel on open and RETURNS to the hamburger on close; Tab is trapped inside; background scroll is locked while open; the hamburger carries `aria-expanded` + `aria-controls`.
